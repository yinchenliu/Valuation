## Mutant Verification

Verified that introducing mutants into 5 distinct P14a behaviors causes immediate assertion failures:

1. **Scale multiplier inversion**: If `printed_scale` returned 1000 instead of `Fraction(1, 1000)` for `"in thousands"`, `convert_filing_to_millions` scaled revenue $9{,}872{,}000$ to $9{,}872{,}000{,}000.0$ instead of $9{,}872.0$, failing `assert inc.revenue == 9872.0`.
2. **Whitespace normalization in unit statement lookup**: If `unit_statement_on_page` failed to normalize line breaks `"(in\nmillions)"` to spaces before regex matching, `test_unit_statement_on_page_line_wrapped` returned `False`, failing `assert stmt is True`.
3. **Duplicate conversion guard**: If the check on `bs.printed_unit_in_millions is not None` in `convert_filing_to_millions` were removed, calling `convert_filing_to_millions` on an already-converted filing would proceed without raising `ValueError`, failing `pytest.raises(ValueError, match="already carry printed_unit_in_millions")`.
4. **Tolerance scaling on thousands**: If `BalanceSheet.printed_total_tolerance()` defaulted to `1.0` for thousands instead of `0.001`, a discrepancy of $0.005$ $M would evaluate to `OK` rather than `FAIL`, failing `assert bs.printed_total_check(diff) is False`.
5. **Format version gating**: If `load_session_extraction` tolerated `"session-extraction-v2"`, calling it with a v2 fixture would proceed without error, failing `pytest.raises(ValueError, match="expected session-extraction-v3")`.
