## Decisions, each with its reason

| Decision | Reason / citation | Why this and not the alternative |
|---|---|---|
| The parse errors' expected text comes from stdlib `json.loads` on the same reply string, in the test | the expectation must exist independently of the code under test (`strategy.md` section 1). `_extract_json` returns these strings unchanged, because they start with `{` and end with `}` | Pasting the message the code printed would photograph the output |
| Two different malformed replies (`{this is not json}`, `{"non_recurring_items": [}`), plus a precondition that the two stdlib errors differ | "both parse errors" can be asserted only if the two are distinguishable | With the same reply twice, one substring would satisfy both assertions |
| The first reply is malformed JSON with braces | only `json.JSONDecodeError` or `KeyError` on the first attempt reaches the retry (`ingestion/claude_extractor.py:1786`). Other first-reply failures are F2 | A reply with no `{` would stop with no retry, and that would lock F2 |
| The years are not asserted in the message | the assignment's step 1 names the ticker, the company and both errors. The years print as a Python list repr, which is formatting and not a requirement | This avoids locking a format |
| `_run_pass2` catches `ValueError` only | anything else, such as an unscripted third call (AssertionError) or `_NetworkReached`, must surface as a test error | A broad catch would hide a guard hit |
| Distinct inputs (`ZQX`, `Zeta Quarry Holdings`, the 2023 litigation item for 40.0) | no value is shared with another test's assertion | — |
