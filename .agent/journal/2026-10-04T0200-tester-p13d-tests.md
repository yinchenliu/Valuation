## Decisions, each with its reason

| Decision | Reason / citation | Why this and not the alternative |
|---|---|---|
| Six prices: 0.0, integer 0, -10.0, nan, inf, -inf | The assignment lists 0, a negative price, nan, inf and -inf. Integer 0 copies the P13b `NO_SHARE_COUNT` set. | A price from the web route can arrive as an int. |
| The "before discounting" test uses a valid share count (10.0), a NaN FCFF and no balance sheet | The share check runs before the price check, so an invalid count would hide the price stop. A NaN FCFF and an absent balance sheet each raise with their own message. | This copies the P13b test. Mutant M2 (price check moved after the bridge) shows that it detects the order. |
| Assert `"market data" in message` on `run_dcf` | Rule 5. Step 1 of `P13d-upside-price` requires the label. | A requirement the code meets. It is locked, so a later edit cannot drop it without notice. |
| Assert `ValueError`, not `Exception` | strategy.md section 2. Without the guard, a zero price in the property raises `ZeroDivisionError`. | `pytest.raises(Exception)` would let M5 (guard removed) pass for the zero and integer-zero prices. |
| No test for a `DCFResult` built with `current_price` omitted | When item 1 removes the `= 0.0` default, construction would raise `TypeError` and that test would turn red. That turns a later fix red (tester.md, "Do not write a test that asserts the default"). | The explicit `current_price=0.0` case covers the same guard. |
| A new helper `_result_with_price` and fresh positive inputs (WACC 25%, FCFF 250, 14 shares, price 40) | "Never a figure another test already asserts." | The programmer's and reviewer's cases (25.0 from 25/20, 20/16) are not reused. |
| Positive `BalanceSheet` sets `short_term_debt=0.0` and `current_portion_lt_debt=0.0` explicitly | `total_debt` reads them (`models/financial_statements.py:221`), and their defaults are item 1. | The net debt arithmetic does not depend on a field default. |
