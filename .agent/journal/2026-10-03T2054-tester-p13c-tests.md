## How the tests reach `config` without the real `.env` (step 1's "say which way")

I use two mechanisms. Both run the shipped `config.py`.

1. **Subprocess sandbox.** Used for steps 1 and 3, and for the "no `.env`" case.
   - `_sandbox` copies `config.py` byte for byte into `tmp_path/box/`, beside a `.env`
     that the test writes. A test asserts the copy is byte-identical:
     `test_the_sandbox_copy_is_the_shipped_config`.
   - It runs `sys.executable` with `cwd=box` and an environment built from nothing but
     `PATH`, `PYTHONPATH=box`, two `PYTHON*` flags, the preset names, and `SYSTEMROOT`
     on Windows.
   - `config.BASE_DIR` is `Path(__file__).parent`, so the copy reads `box/.env` through
     the real `dotenv_values`, by the shipped code path.
   - Each child reports `config.__file__`, and every call asserts it is the sandbox copy.
   - No credential that the pytest process holds reaches the child. This matters,
     because other tests' `import config` puts the real key into pytest's `os.environ`.
   - **Why this way:** the fill happens at import, in a fresh process, from a real
     environment. A subprocess is the only way to test "set before `config` loads"
     without simulating it. The process-boundary cases also need real children:
     `subprocess.run`, and `multiprocessing.get_context("spawn")`, which is uvicorn's
     reloader mechanism (round 1 F1).
2. **Fresh in-process load.** Used for step 2.
   - `_fresh_config` executes the real `config.py` file under a private module name.
   - Beforehand, `dotenv.dotenv_values` is replaced with a function that records the
     path it is asked for and reads the test's own file. `config.py` does
     `from dotenv import dotenv_values`, so the module body binds the replacement.
   - The helper asserts that the shipped code asked exactly once for
     `REPO / ".env"` ("read `.env` once", round 3 amendment).
   - Every credential name, and every name in the test's file, is first registered with
     monkeypatch (set, then deleted). The fill is therefore undone after each test, and
     no real key in `os.environ` is visible during the test.
   - **Why this way:** it gives line and branch coverage on `config.py` itself, and lets
     the label rules be checked one at a time.
